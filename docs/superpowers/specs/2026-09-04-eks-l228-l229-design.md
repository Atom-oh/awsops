## Decisions

- **L228 — mostly shipped; the residue is rate display + the tick**: NodeEniSection already
  renders live 1h In/Out/PktsIn/PktsOut tiles (ec2DiagFleetLive, read-only CloudWatch) with
  the honest disclosure that CloudWatch AWS/EC2 has NO per-ENI dimension — v1's "per-ENI"
  tiles repeated the same instance-level metrics on every ENI card, so v2's single
  instance-level tile row is the honest form of the same data (disclosed structural
  deviation). Residue shipped here: the tiles gain the v1-parity RATE view — avg bytes/s and
  packets/s derived from the 1h sums (sum ÷ 3600, labeled as the 1h average) under the
  cumulative value, so both v1's "avg + packet-rate" reading and v2's cumulative reading are
  present.
- **L229 — Service Resources charts on the /eks/services fleet page**:
  - `ServiceRow` gains `selector` (spec.selector, may be absent — headless/selectorless
    services join nothing and are excluded, disclosed in the caption) and `PodRow` gains
    `labels` (metadata.labels) — both are non-secret metadata (the explorer's no-secret-values
    rule untouched).
  - The services FleetKindPage block additionally fetches pods per cluster (the same
    incluster kind=pods endpoint the nodes kind already uses) and joins per
    (cluster, namespace): a pod matches when EVERY selector key/value matches its labels AND
    its status is Running (v1 semantics — requests of pending/failed pods are not a running
    footprint). Sums use the already-normalized `cpuRequest` (cores → millicores ×1000) and
    `memRequest` (MiB).
  - Two top-15 bar charts ('CPU per Service (millicores)', 'Memory per Service (MiB)'),
    keyed `cluster/namespace/name` (same-name services in different namespaces/clusters must
    not merge). Services with zero matched running pods (or no selector) are excluded rather
    than charted as 0 (absence ≠ zero footprint claim); a caption discloses the exclusions
    and that values are REQUESTS (not live usage) — v1 parity.
  - Honesty gates: charts render only from clusters whose BOTH services and pods fetches
    succeeded (a pods-fetch failure for one cluster must not silently zero its services);
    unreachable-cluster exclusions ride FleetKindPage's existing per-cluster error banners.
- **Drive-bys (batch-42 round-3 review minors, chair-endorsed)**: the batch-42 audit note's
  "리전별 … 1회" → paginated wording + optionsDegradedRegions/IAM/deploy-debt mentions; the

## Round-1 corrections (review-driven)

- **The rate is a true average over a COMPLETE hour bucket (the gate MAJOR)** — the round-0
  rate divided the newest CloudWatch Sum by 3600, but fleetLatest's Values[0] is the
  still-filling current clock-hour bucket, so the displayed rate was systematically
  understated (~12× at :05) — the exact partial-bucket trap metrics.ts documents and fixes
  for its perSecond metrics. fleetLatest gains an opt-in `completeBucketsOnly` (newest bucket
  with ts+Period ≤ now; window doubled so one always exists; NO complete bucket → null, never
  a partial value), the node-eni route opts in, and the tile tooltip/labels say "완결된 직전
  1시간 버킷" — tests pin partial-skipped/complete-picked, the null path, the widened window,
  and that legacy consumers keep Values[0].
- **The audit is 242 items, not 99 (the gate MAJOR)** — the spec header and the batch-43 note
  claimed a "99-item audit" (99 is the API-route count — a conflation); both now say 242.
  The completion claim itself was correct: 0 unchecked of 242.
- **The docs-site services guide documents the new charts (the gate MAJOR)** — the spec's own
  §Testing committed to it and the guide has a chart section: all 4 locales gain a 'Service
  Resources' section with the request-not-usage, Running-only, exclusion, and
  pods-fetch-failure caveats.
- Minors closed: the chart caption names the Running-only filter (the nodes bars use
  all-non-terminal — two deliberate definitions, now labeled); the IAM wiring guard scopes
  command extraction to the @aws-sdk/client-ec2 import block (a future non-EC2 client's
  commands won't be mis-asserted as ec2:*).
- Recorded (pre-existing/accepted): PodRow's `max(sum app, max init)` request formula
  undercounts native restartable sidecars (base code shared with the node bars — follow-up
  candidate, not changed here); parseMem rounds per-container to MiB before summing
  (pre-existing parser); the services page's per-cluster pods fetch is uncached per load
  (2N apiserver GETs — load consideration; the AWS-layer TTL convention doesn't yet extend
  to the incluster route).
