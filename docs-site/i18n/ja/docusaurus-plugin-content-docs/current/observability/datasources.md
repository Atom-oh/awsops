# データソース

**連携 → Datasources** で可観測性エンドポイントを登録し、インスタンスの **探索 →** を開きます。同じプロバイダーを複数登録できます。設定の保存、接続テストの成功、ワークロードの正常性は別の状態です。

## 権限と範囲

- ログイン済みユーザーはインスタンス一覧の参照、Explore、AI クエリ下書き生成を利用できます。
- 管理者は作成・編集・削除・既定インスタンス選択、認証情報管理、接続テストを行います。エンドポイントと設定の詳細も管理者のみに表示されます。
- 登録はグローバル設定です。サイドバーのアカウントを変えてもデータソースの接続先は変わりません。Explore は選択したインスタンス ID を指定します。
- 同じ種類で最初のインスタンスが既定になります。既定マークは選択の優先設定であり、接続や正常性の検証結果ではありません。

## 対応プロバイダー

| プロバイダー | Explore クエリ | 接続テスト |
|---|---|---|
| Prometheus | PromQL、例: `up` | `/-/healthy` |
| Mimir | PromQL、例: `up` | `/ready` |
| Loki | LogQL、例: `{job="varlogs"} \|= "error"` | `/ready` |
| Tempo | TraceQL、例: `{ duration > 500ms }` | `/ready` |
| ClickHouse | 読み取り専用 SQL。まず `SELECT 1` | `/ping` |
| Jaeger | サービス名または `service=frontend&limit=20` などの検索パラメーター | `/api/services` |
| Dynatrace | Metrics API v2 `metricSelector`、例: `builtin:host.cpu.usage:avg` | `/api/v2/metrics?pageSize=1` |
| Datadog | メトリクスクエリ、例: `avg:system.cpu.user{*}` | `/api/v1/validate` の後、1分範囲の `/api/v1/query` |

環境に存在するメトリクス・ラベル・サービス・テーブル名を使用してください。Jaeger Explore は簡潔なトレース検索結果を返し、単独の Trace ID を直接取得命令として扱いません。Dynatrace は Grail DQL ではなく Metrics API v2 を使います。別の Problems ツールには `problems.read` が必要で、メトリクステストではその権限を確認しません。Datadog データソースはメトリクス時系列を照会し、ログや APM トレースは検索しません。

## 接続、テスト、保存

1. **データソース追加**でプロバイダーを選び、名前と API ベース URL を入力します。種類別の URL ヒントを参考にし、正しい Datadog サイトまたは Dynatrace 環境を指定してください。
2. 認証情報を入力します。URL に認証情報を含めないでください。API ベース URL にユーザー情報・クエリパラメーター・フラグメントは指定できません。
3. Loki・Tempo・Mimir でテナントヘッダーが必要な場合は **Org ID (X-Scope-OrgID)** を入力します。
4. 必要に応じてクエリ Timeout と ClickHouse の既定 Database を設定します。実効上限は下表を確認してください。
5. **接続テスト**で成功・失敗を確認します。成功時には往復遅延が表示されます。Datadog は API key と Application key のメトリクス照会権限を検証します。空の照会結果でも接続テストは成功する場合があります。
6. **保存**後に **探索 →** で小さな読み取り専用クエリを実行し、目的のデータセットへのアクセスを確認します。例えば ClickHouse `/ping` は到達性を確認するだけで、クエリ権限の証明にはなりません。

テストは推奨されますが、保存自体はテスト成功を意味しません。編集時も保存済みの秘密値は表示されません。接続先と認証方式を変えずに認証欄を空欄にすると保存値を維持します。編集時のテストが再利用するのは、接続先全体が一致する当該インスタンスの認証情報だけです。ホスト・スキーム・ポート・パスを変更した場合は再入力してください。接続項目を編集すると前のテスト結果は消去されます。

### 認証方式

| 方式 | 用途 |
|---|---|
| None | 認証不要のバックエンド |
| Basic | ユーザー名とパスワード。認証付き ClickHouse など |
| Bearer token | トークン認証。Dynatrace コネクターは Bearer ではなく `Authorization: Api-Token` を送信 |
| Custom header | 最大2組のヘッダー名と値。Host・Content-Length・Authorization などの転送制御ヘッダーは上書き不可 |

Datadog を選ぶと専用の **API key** と **Application key** が選択され、`DD-API-KEY` と `DD-APPLICATION-KEY` として送信されます。Dynatrace はトークン欄が既定で選択され、メトリクス参照には `metrics.read` が必要です。認証情報はサーバー側の Secrets Manager に保存され、フォームには返されません。

### 状態の読み方

| 状態 | 意味と次の確認 |
|---|---|
| 設定保存済み・未検証 | 必要な設定が存在。テストと代表的なクエリで確認 |
| 認証設定が必要 | 必要な保存済み認証情報が不足。管理者に補完を依頼 |
| 接続成功 | 当該プロバイダーのテスト成功。全 API 権限・データセット・ワークロードの検証ではない |
| 状態・設定を確認できない | 設定読取に失敗。空の一覧と判断せず再試行または権限確認 |
| 無効 | 行が無効で、AI 診断ショートカットは表示されない |

## Explore とクエリ制限

インスタンスを選び、ネイティブクエリを確認して**実行**を押します。単一行のクエリ欄は Enter、複数行 SQL は Ctrl+Enter で実行します。クエリ例チップは即時実行しますが、自然言語の例チップは依頼文を入力するだけです。診断シグナルチップがある場合も、選択したクエリを実行します。

Prometheus・Mimir・Loki は **Instant** と 5m・15m・1h・6h・24h・7d を選択でき、Prometheus/Mimir は 30d にも対応します。範囲変更は現在のクエリを再実行します。ほかのプロバイダーにはこの範囲選択欄はありません。直接の範囲リクエストは最短60秒、最長は Prometheus/Mimir が30日、Loki が7日で、評価点は最大5,000です。ネイティブクエリは最大8,000文字です。

| 設定・制限 | 現在の動作 |
|---|---|
| Timeout | 整数秒、1–60、既定10 |
| ClickHouse Timeout | Explore・グラフ・エージェントのクエリ実行上限。実効最大55秒で、56–60は55に短縮。呼び出し側は短縮のみ可能。HTTP 制限はその上に合わせる |
| Prometheus/Mimir Timeout | Explore の上流 API クエリに適用。コネクターの HTTP 12秒より短い最大10秒 |
| ほかの Timeout | Loki・Tempo・Jaeger・Dynatrace・Datadog では保存のみで、現在は適用されない |
| ClickHouse Database | 任意の識別子、最大128文字。`system`・`information_schema` は拒否 |
| ClickHouse 行数 | Explore は最大500行を要求。コネクターの一般上限は1,000行。安全な LIMIT で絞り込む |
| クエリ結果キャッシュ | 設定可能な結果キャッシュ TTL はない。AI 語彙用のスキーマキャッシュは別機能 |

これらのクエリ設定は、すべての接続テストが同じ時間制限を使うことを意味しません。ClickHouse は変更文・SYSTEM・テーブル関数へのアクセスを拒否します。`SELECT 1` または検出済みで許可されたユーザーテーブルを使い、読み取り専用に見えるクエリが全バックエンドで許可されるとは考えないでください。

結果には行・系列数、コネクター往復時間、結果形式が表示されます。Prometheus/Mimir の範囲チャートは最大8系列と Line/Bar 切り替えに対応し、表や注記で追加情報を確認できます。Loki はログビューアー、Tempo/Jaeger は簡潔なトレース結果と duration バーを提供します。切り詰め・部分的カバレッジ・空結果の表示を確認してください。少量または空の結果だけでは、ワークロードの正常性や網羅性は証明できません。

## AI クエリ下書き、チャット、診断

### 生成後に確認し、実行する

自然言語で依頼し、**AI で生成**またはその入力欄の Enter を押します。クエリが入力され、語彙やスキーマの警告が出る場合があります。**生成したクエリは自動実行されません。** 内容を確認し、別途**実行**を押してください。自然言語入力は4,000文字に制限されます。

下書きは選択したインスタンスの利用可能なスキーマ語彙を参照します。スキーマが未取得・古い・不完全な場合はバックグラウンド更新が始まることがあり、不完全なスキーマでも生成される場合があります。名前・時間範囲・権限・警告を確認してください。結果キャッシュとこのスキーマキャッシュは別の概念です。

### 既定インスタンスの診断

Prometheus・ClickHouse・Loki・Mimir・Tempo の**有効かつ設定済みの既定インスタンス**では、**AI で診断**から `/assistant` を開き、セクション指定済みの依頼文を入力できます。Prometheus/ClickHouse は `/observability`、Loki/Mimir/Tempo は `/monitoring` です。これらは依頼文のセクション選択子です。リンクを開いても自動送信せず、確認して自分で送信すると新しい会話を開始します。

ネイティブチャットツールは種類ごとの既定インスタンスを使います。別のインスタンスの根拠が必要なら Explore で選択してください。既定以外の行にはこの診断ショートカットはありません。エージェントは利用可能な読取・クエリ・スキーマツールを使い、NLB・セキュリティグループ・Kubernetes の固定診断パイプラインを保証しません。

**Datadog・Dynatrace は Explore と AI クエリ下書きに対応しますが、ネイティブチャットのゲートウェイターゲットと自動診断レポート収集は既定で接続されていません。** Jaeger も Explore・下書きに対応しますが、ネイティブチャットターゲットや自動レポート収集器はありません。登録だけでこれらの経路は追加されません。

ワーカーによる外部根拠の収集は現在 Prometheus・Mimir・Loki・Tempo・ClickHouse のみを対象とし、`datasource_diagnosis_enabled` と AgentCore・integrations・workers の依存機能を有効にする必要があります。登録だけでは収集は有効になりません。利用不能・不完全な根拠はレポートでも区別する必要があります。

対応ベンダーの hosted MCP プリセットは **Connectors** の別経路で、認証情報・デプロイゲート・ツール許可リストも独立しています。Datadog・Dynatrace データソースの保存で hosted MCP は有効になりません。v2 には `datasource` チャットルートやライブ Steampipe チャットクエリ経路はありません。

## トラブルシューティングと安全な利用

- 認証失敗では API サイト・環境、認証方式、必要な読取スコープを確認します。メトリクステストの成功は Problems API 権限の証明ではありません。
- Timeout ではコネクターからの到達性とネットワーク規則を確認し、クエリ・期間を絞ります。プライベート接続先には適切なコネクターネットワークアクセスが必要です。
- HTTP(S) のプライベートデータソースは利用できますが、メタデータ・ループバック・リンクローカルなどの禁止された特殊アドレスは拒否されます。リダイレクトと安全でない URL 形式も拒否します。v2 に Allowed Networks 例外編集機能はありません。
- 設定読取・保存・削除・既定変更が失敗した場合は表示されたエラーから再試行します。行や以前の表示が変わらないだけで成功とは判断できません。
- 切り詰め・部分的・古い・未評価の根拠は、元データと時間範囲を確認して要求を絞ります。利用不能な測定値を正常なゼロとして解釈しないでください。
