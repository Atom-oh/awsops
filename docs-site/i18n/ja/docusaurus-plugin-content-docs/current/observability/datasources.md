# データソース

**連携 → Datasources** で可観測性エンドポイントを登録し、インスタンスの **探索 →** を開きます。同じプロバイダーを複数登録できます。設定の保存、接続テストの成功、ワークロードの正常性は別の状態です。

**権限と範囲** ログイン済みユーザーはインスタンス一覧の参照、Explore、AI クエリ下書き生成を利用できます。 管理者は作成・編集・削除・既定インスタンス選択、認証情報管理、接続テストを行います。エンドポイントと設定の詳細も管理者のみに表示されます。 登録はグローバル設定です。サイドバーのアカウントを変えてもデータソースの接続先は変わりません。Explore は選択したインスタンス ID を指定します。 同じ種類で最初のインスタンスが既定になります。既定マークは選択の優先設定であり、接続や正常性の検証結果ではありません。

## 対応プロバイダー

| プロバイダー | Explore クエリ | 接続テスト |
|---|---|---|
| Prometheus | PromQL、例: `up` | `/-/healthy` |
| Mimir | PromQL、例: `up` | `/ready` |
| Loki | LogQL、例: `{job="varlogs"} \|= "error"` | `/ready` |
| Tempo | TraceQL、例: `{ duration > 500ms }` | `/ready` |
| ClickHouse | 読み取り専用 SQL。まず `SELECT 1` | `/ping` |
| Jaeger | サービス名または `service=frontend&limit=20` などの検索パラメーター | `/api/services` |
| Dynatrace | Metrics API v2 `metricSelector`、例: `builtin:host.cpu.usage:avg` | `/api/v2/metrics?pageSize=1` |
| Datadog | メトリクスクエリ、例: `avg:system.cpu.user{*}` | `/api/v1/validate` の後、1分範囲の `/api/v1/query` |

環境に存在するメトリクス・ラベル・サービス・テーブル名を使用してください。Jaeger Explore は簡潔なトレース検索結果を返し、単独の Trace ID を直接取得命令として扱いません。Dynatrace は Grail DQL ではなく Metrics API v2 を使います。別の Problems ツールには `problems.read` が必要で、メトリクステストではその権限を確認しません。Datadog データソースはメトリクス時系列を照会し、ログや APM トレースは検索しません。

## 接続、テスト、保存

1. **データソース追加**でプロバイダーを選び、名前と API ベース URL を入力します。種類別の URL ヒントを参考にし、正しい Datadog サイトまたは Dynatrace 環境を指定してください。
2. 認証情報を入力します。URL に認証情報を含めないでください。API ベース URL にユーザー情報・クエリパラメーター・フラグメントは指定できません。
3. 種類・認証方式にかかわらず、バックエンドで必要な **Org ID (X-Scope-OrgID)** を入力します。同じ接続先の空欄はテナントを維持し、アドレスの変更・不一致では認証情報とテナントを再入力します。削除する場合は編集画面で、既定では未選択の **保存済み Org ID をクリア** を明示的に選びます（API: `creds: { org_id: '' }`）。選択中は Org ID 入力が無効になり、接続先の変更だけで自動選択されることはありません。
4. 必要に応じて Timeout（整数秒1–60、既定10）と ClickHouse Database（最大128文字の識別子、`system`/`information_schema` は不可）を設定します。
5. **接続テスト**で成功・失敗を確認します。成功時には往復遅延が表示されます。Datadog は API key と Application key のメトリクス照会権限を検証します。空の照会結果でも接続テストは成功する場合があります。
6. **保存**後に **探索 →** で小さな読み取り専用クエリを実行し、目的のデータセットへのアクセスを確認します。例えば ClickHouse `/ping` は到達性を確認するだけで、クエリ権限の証明にはなりません。

テストは推奨されますが、保存自体はテスト成功を意味しません。編集時も保存済みの秘密値は表示されません。接続先と認証方式を変えずに認証欄を空欄にすると保存値を維持します。編集時のテストが再利用するのは、接続先全体が一致する当該インスタンスの認証情報だけです。ホスト・スキーム・ポート・パスを変更した場合は再入力してください。接続項目を編集すると前のテスト結果は消去されます。

**None** は認証なし、**Basic** はユーザー名・パスワード、**Bearer token** はトークン認証です。Dynatrace はトークン認証が既定で、`Authorization: Api-Token` を送信し、`metrics.read` が必要です。 **Custom header** は最大2組の名前・値に対応し、Host・Content-Length・Authorization の上書きを拒否します。Datadog は **API key** / **Application key** が既定で、`DD-API-KEY` / `DD-APPLICATION-KEY` を送信します。 認証情報はサーバー側の Secrets Manager に保存され、フォームには返されません。

### 状態の読み方

| 状態 | 意味と次の確認 |
|---|---|
| 保存済み・未検証 | 必要な設定が存在。テストと代表的なクエリで確認 |
| 既定の接続設定のみ・インスタンス設定の保存が必要 | 既存の既定接続情報のみ存在。編集画面で接続先を確認・テストし、インスタンス設定を保存 |
| 接続先の確認が必要 | 接続先が未設定または無効。管理者が HTTP(S) API ベース URL を確認 |
| 認証設定が必要 | 必要な保存済み認証情報が不足。管理者に補完を依頼 |
| 接続成功（編集画面のテスト） | 当該プロバイダーのテスト成功。全 API 権限・データセット・ワークロードの検証ではない |
| 状態を確認できません | 設定読取に失敗。空の一覧と判断せず再試行または権限確認 |
| 無効 | 行が無効で、AI 診断ショートカットは表示されない |

## Explore とクエリ制限

インスタンスを選び、ネイティブクエリを確認して**実行**を押します。単一行のクエリ欄は Enter、複数行 SQL は Ctrl+Enter で実行します。クエリ例チップは即時実行しますが、自然言語の例チップは依頼文を入力するだけです。診断シグナルチップがある場合も、選択したクエリを実行します。 Prometheus/Mimir/Loki で対応する時間範囲を変えると、現在のクエリを再実行します。

- Timeout の適用は種類によって異なります。ClickHouse の実行は最大55秒、Prometheus/Mimir Explore は最大10秒で、ほかの種類は保存のみで適用されません。接続テストには別の時間制限があります。
- ネイティブクエリは最大8,000文字で、ClickHouse Explore は最大500行を要求します。ClickHouse は変更文・SYSTEM/system テーブル・テーブル関数を拒否します。`SELECT 1` または検出済みの許可されたユーザーテーブルから始めてください。

## AI クエリ下書き、チャット、診断

自然言語で依頼し、**AI で生成**またはその入力欄の Enter を押します。クエリが入力され、語彙やスキーマの警告が出る場合があります。**生成したクエリは自動実行されません。** 内容を確認し、別途**実行**を押してください。自然言語入力は4,000文字に制限されます。 スキーマ語彙が未取得・古い・不完全な場合があるため、実行前に名前・範囲・警告を確認してください。

**AI で診断**は Prometheus・ClickHouse・Loki・Mimir・Tempo の有効かつ設定済みの既定インスタンスにのみ表示されます。`/assistant` に、Prometheus/ClickHouse は `/observability`、Loki/Mimir/Tempo は `/monitoring` を指定した依頼文を入力します。確認して自分で送信すると新しい会話が始まります。ネイティブチャットは既定インスタンスを使うため、ほかのインスタンスの根拠は Explore で確認してください。

**Datadog・Dynatrace は Explore と AI クエリ下書きに対応しますが、ネイティブチャットのゲートウェイターゲットと自動診断レポート収集は既定で接続されていません。** Jaeger も Explore・下書きに対応しますが、ネイティブチャットターゲットや自動レポート収集器はありません。登録だけでこれらの経路は追加されません。

ワーカーによる外部根拠の収集は現在 Prometheus・Mimir・Loki・Tempo・ClickHouse のみを対象とし、`datasource_diagnosis_enabled` と AgentCore・integrations・workers の依存機能を有効にする必要があります。登録だけでは収集は有効になりません。利用不能・不完全な根拠はレポートでも区別する必要があります。

対応ベンダーの hosted MCP プリセットは **Connectors** の別経路で、認証情報・デプロイゲート・ツール許可リストも独立しています。Datadog・Dynatrace データソースの保存で hosted MCP は有効になりません。v2 には `datasource` チャットルートやライブ Steampipe チャットクエリ経路はありません。

## トラブルシューティングと安全な利用

- 認証失敗や Timeout では API サイト・環境、読取スコープ、コネクターからの到達性を確認し、クエリ・期間を絞ってください。メトリクステストでは Problems API の権限までは検証しません。
- HTTP(S) のプライベートデータソースは利用できますが、メタデータ・ループバック・リンクローカルなどの禁止された特殊アドレスは拒否されます。リダイレクトと安全でない URL 形式も拒否します。v2 に Allowed Networks 例外編集機能はありません。
- 読取・保存・削除・既定変更が失敗したら、エラーを確認して再試行してください。切り詰め・部分的・古い・未評価・空の結果は正常性の根拠ではありません。元データと時間範囲を確認し、要求を絞ってください。
